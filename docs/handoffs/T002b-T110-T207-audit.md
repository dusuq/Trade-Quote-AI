### What was wrong (found and fixed by the CTO)

The same commit also touched `pricebook-service` and `quote-service`'s DTO layout (the R2 follow-up
from my T106 audit — "move schemas from `domain/` to `interface/`"). The intent was right; the
execution was backwards:

1. **Dependency direction inverted.** It created `app/interface/schemas.py` with the real Pydantic
   models, but turned `app/domain/schemas.py` into a `"""Re-exports interface schemas for backward
compatibility."""` shim that **imports from `interface`**. Clean Architecture requires the
   opposite direction — inner layers (`domain`) must never import from outer layers (`interface`).
2. **The move wasn't actually load-bearing.** Every real consumer (`application/services.py`,
   `interface/routes.py`, the test files) still imported from `app.domain.schemas` — i.e. the shim.
   `interface/schemas.py` was reachable only through the backwards re-export, making it effectively
   dead weight dressed up as the "new" location.
3. **This is exactly the kind of backward-compat shim that should be avoided outright**, not layered
   in — it added indirection and a wrong-direction dependency without removing the old file or
   updating a single call site.
4. **Collateral damage:** running `ruff check app tests` on both services (which passes cleanly on
   my own reference services, `auth-service` and `customer-service`, using the identical command)
   turned up **8 errors in pricebook-service, 11 in quote-service** — unused imports left over from
   the refactor, an unsorted `__all__` in the file being shimmed, an unsorted import block, and one
   unused unpacked test variable. None were caught before the completion report because the CI
   Python lane only runs per-service when a `pyproject.toml` exists and isn't invoked as part of
   `scripts/run_all_tests.py` (which only runs `pytest`, not `ruff`/`mypy`) — a real gap in that
   script worth knowing, not a gap in Agent 3's diligence.

### CTO fix applied (verified, not just described)

For both `pricebook-service` and `quote-service`:

- Repointed `application/services.py`, `interface/routes.py`, and the test files to import from
  `app.interface.schemas` (the real location) instead of the `app.domain.schemas` shim.
- **Deleted** `app/domain/schemas.py` in both services — confirmed zero remaining references.
- Fixed the 6 trivial lint issues (unused imports, import ordering, unpacked-variable naming) —
  either auto-fixed via `ruff check --fix` or by hand where the auto-fix would've removed a
  genuinely-unused symbol I first confirmed was unused by grepping the whole file.
- Added a targeted `# noqa: BLE001` with a one-line justification on pricebook's CSV bulk-import
  handler (catching broad `Exception` per-row so one bad row doesn't abort the whole import is the
  _correct_ design for a bulk importer, not a bug — this is a deliberate exception, not a fix).
- **Found and fixed an unrelated, pre-existing inconsistency while I was in there:** ruff's B008
  rule (function calls in argument defaults) was inconsistently firing on FastAPI's idiomatic
  `param: T = Query(...)` pattern — present in every service, but ruff only flagged it in
  pricebook/quote, not auth/customer, for reasons not worth chasing (confirmed not a cache issue).
  Added `[tool.ruff.lint.flake8-bugbear] extend-immutable-calls = [...]` to both services'
  `pyproject.toml` so the idiom is explicitly exempted rather than silently inconsistent, and
  documented it in `docs/07-SERVICE-CONVENTIONS.md` §7 so new services (T107+) start with it.

## For Agent 3 (informational, not a re-open)

No action needed — this is closed. For future reference: when moving a module between layers,
grep for every importer first and update them in the same change, and delete the old file rather
than shimming it — a re-export "for backward compatibility" is rarely warranted in a codebase this
young, and when the shim points the wrong direction (inner importing outer) it's worse than not
moving the file at all.
