# Infrastructure

- **Owner Agent:** Agent 4 — Opus + Sonnet 4.6
- **Bounded Context / Purpose:** Docker, deployment, edge, CI/CD, monitoring

## Layout

| Path             | What                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| `services.yml`   | **Canonical registry** of every deployable unit — the source of truth |
| `docker/`        | Local dev data stack (Postgres, Redis, MinIO, OpenSearch, Qdrant)     |
| `db/migrations/` | Ordered SQL migrations                                                |
| `monitoring/`    | Prometheus, Grafana, Loki, Alertmanager, blackbox-exporter            |
| `cloudflare/`    | Terraform for DNS, TLS, WAF, rate limits, cache policy                |

Per-unit `Dockerfile`, `.dockerignore`, and `fly.toml` live **next to the code
they deploy** (`services/<name>/`, `apps/api-gateway/`), not here.

## The registry is the source of truth

`infra/services.yml` defines every deployable unit: path, runtime, port,
scaling, criticality. Four things are derived from it:

```
infra/services.yml
   ├─→ services/*/Dockerfile, .dockerignore, fly.toml   (scripts/gen_infra.py)
   ├─→ apps/api-gateway/{Dockerfile,fly.toml}           (scripts/gen_infra.py)
   ├─→ monitoring/prometheus/targets/*.json             (scripts/gen_infra.py)
   └─→ the deploy matrix                                (scripts/deploy_matrix.py)
```

**Never hand-edit a generated file.** They carry a `GENERATED by` banner, and
CI runs `gen_infra --check`, which fails if a committed artifact no longer
matches the registry. That check is the reason a port can't silently drift out
of alignment between the gateway, the containers, and the monitoring.

```bash
pnpm infra:gen      # regenerate after editing services.yml
pnpm infra:check    # verify committed artifacts are in sync (what CI runs)
```

### Adding a service

1. Add it to `infra/services.yml` (pick the next free port).
2. Add the matching `<NAME>_SERVICE_URL` default to
   `apps/api-gateway/src/config.ts` — `tests/infra` asserts the ports agree.
3. `pnpm infra:gen`
4. `python -m pytest tests/infra -q`
5. Commit the registry change and the generated files together.

## Local stacks

```bash
pnpm dev:up        # data stack: Postgres, Redis, MinIO, OpenSearch, Qdrant
pnpm monitor:up    # Grafana :3001 · Prometheus :9090 · Alertmanager :9093
```

The two are separate on purpose: you restart Grafana without bouncing the
database, and you can point monitoring at a remote environment without running
local infra at all.

## Deployment

Fly.io for the gateway and all 11 services; Vercel for `apps/web`; Cloudflare in
front. Merge to `main` → CI → `deploy.yml` → manual approval on the `production`
environment → rolling deploy of only the changed units, gateway last.

Full procedures — first-time setup, secrets, rollback, per-alert response — are
in [docs/12-PRODUCTION-RUNBOOK.md](../docs/12-PRODUCTION-RUNBOOK.md).

## Monitoring

Availability and latency come from blackbox-probing every unit's `/health`,
which needs **no application code change**. Alerts route by severity: `page` →
PagerDuty, `ticket` → Slack. Every alert links to a runbook section, and
`tests/infra` fails if a link doesn't resolve.

**Gap worth stating plainly:** there are no in-application metrics (request
rate, error rate, per-endpoint latency) because no service exposes `/metrics`
yet. That needs instrumentation across all 12 units and is tracked as **T309b**.
See the runbook's "Known gaps" for the full list.

## Definition of Done

- Clean Architecture layering (domain → application → infrastructure → interface)
- Contract published/consumed via `packages/types` (OpenAPI/gRPC + domain events)
- Tenant-scoped (`tenant_id` + RLS) where data is persisted
- Tests: unit + integration (≥80% on domain logic)
- Passes the 12 Quality Gates → Agent 1 sign-off
- `TASKS.md` box checked + `tracking/PROGRESS-TRACKER.csv` row set to DONE
